# 做一个自己的多平台媒体链接下载器：Electron + yt-dlp + FFmpeg 实践

## 一、为什么做这个项目

平时从 YouTube、TikTok、Instagram、抖音和 Bilibili 保存自己拥有权利或已经获得授权的公开视频时，不同平台的网页结构、分享链接格式和下载方式并不统一。于是我做了一个 Windows 桌面工具，把“粘贴链接、解析信息、选择质量、加入队列、保存文件”整理成一个简单流程。

项目地址：待补充 GitHub 仓库地址

## 二、整体技术方案

项目使用 Electron 构建桌面应用，界面由 HTML、CSS 和原生 JavaScript 组成，主进程负责调用本地命令，渲染进程负责交互和状态展示。

- Electron：提供 Windows 桌面窗口和 IPC 通信
- yt-dlp：负责解析平台链接、读取标题/作者/封面/格式并执行下载
- FFmpeg：在需要时合并视频和音频流
- Playwright：在抖音短链接需要跳转时，使用后台浏览器完成页面解析
- 原生 SVG + CSS：绘制平台 Logo 和界面视觉效果，不依赖远程图片资源

核心流程如下：

1. 用户粘贴网页 URL、抖音短链接或完整分享文案。
2. 应用先从输入文本中提取并标准化 URL。
3. 普通平台交给 yt-dlp 查询媒体信息。
4. 抖音短链接优先走后台浏览器解析，必要时才提示用户完成验证。
5. 解析结果展示标题、作者、时长、封面和可用格式。
6. 下载任务进入队列，实时更新进度，完成后保存媒体文件和可选元数据。

## 三、为什么选择 yt-dlp

如果为每个平台单独维护解析接口，平台接口变化后维护成本会很高。yt-dlp 已经把大量平台适配逻辑封装好，应用只需要负责参数组合、进程管理、JSON 结果解析和错误提示。

为了提高兼容性，应用会把 yt-dlp 的结构化输出转换成统一的媒体对象，例如：

```json
{
  "title": "视频标题",
  "uploader": "作者",
  "duration": 120,
  "thumbnail": "封面地址",
  "formats": []
}
```

这样界面不需要知道每个平台的字段差异，后续增加平台时也更容易维护。

## 四、抖音链接的特殊处理

抖音常见输入不只有标准网页地址，还包括 `v.douyin.com` 短链接和“复制此链接，打开抖音搜索”的完整分享文案。项目会先从文本中提取 URL，再根据链接类型进入不同流程。

短链接解析采用后台浏览器优先策略，避免每次点击解析都主动打开浏览器。如果平台要求新鲜 Cookie 或人工验证，才会打开可见浏览器窗口，让用户在自己的登录状态下完成验证。

这里没有尝试绕过 DRM、验证码或平台权限限制。对于登录专属、私密或受地区限制的内容，应用会直接显示原因，并要求用户使用自己有权访问的公开内容。

## 五、界面设计

界面采用卡片式布局，分为四个区域：

- 顶部工具栏：应用名称、语言切换、主题切换和保存位置
- Hero 区域：项目标题、支持平台 Logo 和视觉焦点
- 链接输入区：支持 URL 和分享文案
- 内容区：左侧展示媒体详情，右侧展示下载队列

平台 Logo 使用内嵌 SVG 绘制，避免依赖外部图片 CDN。主题使用 CSS 变量实现，切换时只修改根节点的 `data-theme`，中英文文案则通过统一的消息字典更新。

## 六、运行项目

需要 Node.js 20 或更高版本，并准备好 yt-dlp 和 FFmpeg：

```bash
npm install
npm start
```

可以把 `yt-dlp.exe` 和 `ffmpeg.exe` 放入应用旁边的 `bin/` 目录，或者将它们加入系统 PATH。开发检查命令如下：

```bash
npm run check
```

## 八、总结

这个项目的重点不是重新实现每个平台的下载协议，而是把成熟的媒体解析工具封装成更易用的桌面工作流。Electron 负责桌面体验，yt-dlp 负责平台适配，FFmpeg 负责媒体处理，三者组合后可以用较少的代码实现一个可扩展的多平台媒体下载器。

使用此类工具时，请只保存自己拥有权利或已经获得授权的内容，并遵守对应平台的服务条款和当地法律法规。
